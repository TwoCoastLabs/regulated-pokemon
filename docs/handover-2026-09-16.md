## 3. What was decided recently, and why

- **The blocks prompt is not the default.** On the strong model it read
  below the baseline band (105–107 vs 111–114); on the weak model above
  it (95–99 vs 93–97). A change that helps one model and hurts the other
  is model-specific tuning under the project's rule, so it stays behind
  `--prompt blocks`. Findings §21, M3 bank legs.
- **The first-call listing nomination is not the prompt's doing.** It
  survived all three prompt arms (203/215/255 of 411 on the strong
  model), so the fix moved to the grammar: the offered door.
- **The offered door (S4a) is built.** The listing route is in the
  grammar only when the driver would accept it, using the executor's own
  two ask-only checks before the call instead of after. The porch
  reading on the strong model went from 2/20 one-call answers to 17/20,
  calls per answer 2.25 to 1.15, three-call exchanges 4 to 0. The weak
  model was 20/20 both ways. Findings §22. The pre-registered bank gate
  is in [offered-door.md](offered-door.md) and in epic #118's S4a line.
- **Refusal feedback stays a flag** (`--refusal-feedback`): C against B
  gave no number the churn band could not explain.
- **Regex stays, for now.** The user reviewed the session's pattern
  matching (about 15 id-derived scan sites and about 13 hand-written
  English word lists in `src/session/session.ts`) and decided to keep
  it. The agreed direction: the id-derived scans become a surface-form
  index; the English lists become a language pack; retrieval could later
  be an off-the-shelf search provider behind the S3 seam, out of CI,
  metered by recall@k.
- **Plain terms.** Reports and docs say "correct-decline rate" and "the
  lowest of the usefulness numbers"; coined phrases and analogies are
  out. Written into `CLAUDE.md` by PR #178.

## 5. Working conventions the next session must keep

- Sync first: `git fetch origin main`, branch from `origin/main`. Check
  `git branch --show-current` before starting a server; the worktree has
  silently reverted to its base branch after a model switch or resume.
- Verify before a PR: `npm run lint`, `npm run test:coverage`,
  `npm run app:build`, and one live porch round through
  `npm run session:trace` when the driver changed.
- Commit goal-first: what the change is for in the project's terms,
  then how it works, then the mechanism. Same for PR text and findings.
- `git add -A -- . ':!.claude'`; never commit `.claude/`.
- Never bare `git stash` or `git stash pop`; the stash stack is shared.
- `gh` fails outside the repo; run it from the worktree or pass
  `-R TwoCoastLabs/regulated-pokemon`.
- zsh does not word-split unquoted variables; use arrays for flag lists
  in shell scripts, or a leg fails with "unknown argument" (no money
  spent, but no data either).
- Report every metric as count and percentage together. Enforcement
  zeros state their denominator. Enforcement and usefulness are reported
  separately. Model errors and harness factors are listed separately.
- Prompts are structural, never tuned to one model; any prompt change
  runs on both models, and a change that helps one and hurts the other
  is withdrawn.
- Keys live only in `.env`. Never in a tracked file, commit message, log
  paste or error report.
- Every findings claim carries a number and the run it came from.
